# 变更记录：应用广场对齐与固件块 `full_flash`

日期：2026-10-22。基线：`main` `7f6e3e2`（CLI 0.2.2）。

这次把应用站广场、我的应用、详情和编辑里 CLI 还没对齐的读写补上，并把固件工具块的 `full_flash` 写进目录和技能文档。烧录、USB、容器安装仍然不在 CLI 里执行。

对照规格是 [app-plaza-cli-sync.md](app-plaza-cli-sync.md)。Markdown 转应用块见 [md-to-app.md](md-to-app.md)。Agent 实际读的是 `skills/sensecraft-apps/`，不读本文。

## 验证

`SENSECRAFT_AI_HOST` 未设置时，`go test ./... -count=1` 全部通过。

本机若把 `SENSECRAFT_AI_HOST` 设成含 `test-` 的地址，应用站链接会变成 `https://test-app.seeed.cc`。`TestAppConsoleURLs`、`TestAppCreateAttachesConsoleURLsInSandbox`、`TestRecameraConsoleURLs` 断言的是正式站 `https://app.seeed.cc`，会失败。这是 host 映射，去掉该环境变量后再跑即通过。

没有对生产网关做写操作冒烟。广场热门第一页与网页的 `app_id` 顺序，需要在同一场活动进行中时用真实 Access Key 再对一次。

## 没有做

| 项 | 原因 |
| --- | --- |
| 烧录、USB、容器安装 | CLI 只写 `deployment.blocks`。执行仍是 L3 |
| `app import-md` | 编辑器保存的是块数组。转换步骤写在 `docs/md-to-app.md` |
| `privacy=1` | 运营审核通过后的公开态。CLI 只发 `2`（提交审核）和 `0`（私有化） |
| 退出已参加的活动 | 不传 `activity_id` 时服务端保留原标签 |
| 落地页热度分、点赞后冻结卡片顺序 | 网页展示层。CLI 每次都是新请求 |
| 硬件 BOM 的 `bom` 筛选 | 网页开关仍关闭 |
| 分享卡片、列表机翻、按作者或设备搜索 | 网页没有对应请求，或纯前端 |
| 把法律声明改成 vercel 链接 | 声明仍是控制台 `/legal/{lang}/declaration` |
| 提交 `sensecraft-app` 的图标时间戳文件 | 与本仓库无关 |

`app list` 两个可见性 flag 都不传时，仍然是「我的应用」，没有改成广场公开列表。

## 1. 列表

文件：`cmd/app/app.go`、`internal/service/open_api_app.go`。

接口仍是 `GET /flow/app/v2/list_app`。

| 命令 | 发出的 query |
| --- | --- |
| `--public` | `be_public=1` |
| `--mine`，或两个可见性 flag 都不传 | 不传 `be_public` |
| `--sort popular\|newest\|likes` | `sort_by`。其它值在发请求前拒绝。不传 `--sort` 时不传 `sort_by` |
| `--sort popular` 且没写 `--priority-activity-id` | 先 `GET /activity/list`，取第一场正整数 `activity_id` 填 `priority_activity_id`。列表失败或为空则不传该参数，列表仍成功 |
| `--priority-activity-id` | 只允许和 `--sort popular` 一起用，且必须是正整数。`newest` / `likes` 带上会直接拒绝 |
| `--tag-id` | `tag_id`。空字符串不传。可与热门同时存在 |
| `--likes` | `mark_type=1` 且 `be_public=1` |
| `--collections` | `mark_type=0` 且 `be_public=1` |
| `--mark-type` | 只接受 `1` 或 `0`。帮助里不再写 `like` / `star` |

`--likes`、`--collections` 与 `--mine` 互斥，两者彼此也互斥。和 `--mark-type` 同时给出时，数值必须一致。

沙箱样例列表会带上这些 query，测试能看出 flag 有没有被丢掉。

## 2. 进行中的活动

新命令：`app activity list`。只读，没有 `--yes`。可加 `--sandbox`。

`GET /activity/list`，不传 `time`。stdout 是 `{ "list": [ { activity_id, name, tag_ids, start_time, end_time } ] }`。`activity_id` 打成数字。缺正整数 `activity_id` 或缺 `name` 的行丢掉。`tag_ids` 只保留正整数并去重。

命令结束后的活动 Notice 还在，不代替这个命令。

## 3. 点赞、收藏、部署计数

都走 `POST /flow/app/v2/mark_app`，L2，需要 `--yes`。

| 命令 | `op_type` |
| --- | --- |
| `app like` | `1` |
| `app unlike` | `0` |
| `app collect` | `3` |
| `app uncollect` | `2` |
| `app mark-deploy` | `4` |

`mark-deploy` 只记公开详情上的一次部署或下载，不连设备，也不做网页那 1500ms 去重。每次命令记一次。

接口返回空对象时，stdout 仍补上 `app_id` 和 `op_type`。重复点赞或收藏按网页一样再送一次，不先 `view` 再决定。

## 4. 克隆

`app clone --id <源> --yes`，可选 `--name`。

`POST /flow/app/v3/clone_app`。源应用 `allow_clone` 为 `0` 时拒绝，不发 POST。不传 `--name` 时名称是 `Clone_` 加源名称前 54 个字符。stdout 带新 `app_id`、`console_url`、`detail_url`，链接规则与 `app create` 相同。不把源应用的 `be_public` 抄过来，也不再调 `publish`。

## 5. 撤回审核和私有化

两条路分开：

| 状态 | 命令 | 请求 |
| --- | --- | --- |
| `be_public=2` 审核中 | `app withdraw --id --yes` | `POST /flow/app/v3/callback_sketch`，body 只有 `app_id` |
| `be_public=1` 已公开 | `app unpublish --id --yes` | `POST /flow/app/v3/edit_privacy_app`，`privacy=0` |
| `be_public=0` 私有 | 撤回会拒绝 | 提示无需撤回 |

`withdraw` 先看 sketch，并要求是所有者。已公开时提示改用 `unpublish`。成功 stdout 带 `app_id` 和 `be_public: 0`。

广场列表菜单在审核中仍可能走 v2 `edit_privacy_app`。CLI 以详情页为准，审核中只走 `withdraw`。

## 6. 竞赛报名补 `allow_clone`

仍用已有的 `app update --activity-id`，没有给 `app create` 加活动参数。

带了 `activity_id` 时：

- 活动列表请求成功、但该 id 不在进行中列表里：不发 `update_app`，避免整单被 `25000` 丢掉。活动列表本身失败时不拦，仍交给服务端。
- 这次 JSON 没写 `allow_clone`，且当前 sketch 还不是 `1`：写入 `allow_clone=1`。JSON 里已经写了的值不动。已经是 `1` 的也不改。
- `tags` 继续被剥掉，不发送。

## 7. 详情和编辑链接改到应用站

API 仍在 AI host。只有页面链接换了。

| 场景 | URL |
| --- | --- |
| 编辑 `console_url` | `https://app.seeed.cc/application/edit?id=<app_id>` |
| 我的详情 `detail_url` | `https://app.seeed.cc/view-application/<app_id>-<slug>?tab=custom&from=my-apps` |
| 广场公开详情 | `https://app.seeed.cc/view-application/<app_id>-<slug>?tab=public&from=application-store` |

`SENSECRAFT_AI_HOST` 含 `test-` 时，origin 换成 `https://test-app.seeed.cc`。

`slug` 与网页 `formatToTitleCase` 一致：先转小写；字母、数字、下划线和中日韩统一表意文字保留，其余换成 `-`；连续 `-` 合并；去掉首尾 `-`。名称为空时路径只有 `app_id`。

`from=my-apps` 留在「我的」链接上，详情才会读 sketch 封面。公开链接不带它。

`app create` 和 `app clone` 注入这两条链接。`app update` 不注入。模型详情仍是 `https://sensecraft.seeed.cc/ai/model/detail?...`。法律声明、Wiki、AI 首页不改到应用站。

`recamera open` 的应用 `console_url` 使用同一套应用站路径，并带上应用名做 slug。模型仍走 `/ai/model/detail`。

列表项若有非空 `web_link`，技能文档要求把外链给用户，不要再拼 `view-application`。CLI 没有改列表 JSON 里的字段。

## 8. 固件块 `full_flash`

只改目录和文档，没有烧录命令。

`app blocks` 里 `flash-firmware` 的 `config_keys` 增加 `full_flash`。字段摊平在块上。

- 布尔，默认 `false`。缺字段当 `false`。`"true"` 和 `1` 读成 `true`。
- 只在这些 SKU 上保留：Indicator `114993068`（D1S / D1L / D1Pro 别名同一行）、Watcher `113991315` / `113991275`、E1001 `100073581`、E1002 `100017057`、1.47 寸触摸 `100069905`、Sticky `100056818`。其它设备编辑器会清回 `false`。
- `muse_gadget: true` 时必须同时写 `full_flash: true`。编辑器会强制勾上，用户不能单独取消。
- `firmware_url` 仍是链在 `0x20000` 的 `muse-gadget.bin`。`flash_address` 保持设备默认，不要写成 `0x20000`。
- `full_flash: true` 表示先整片擦除再写。Muse 关闭时，E1001 / E1002 还会重写 `0x0` 引导和 `0x8000` 分区表，应用仍在 `0x90000`。Indicator、1.47 寸、Sticky、Watcher 的非 Muse 镜像本身是 `0x0` 合并包，这个字段只打开整片擦除。
- Muse 镜像用自己的分段，并整片擦除。不要把 reTerminal 原厂引导写进 Muse 镜像。
- 不写 SDK token、`flash_target`、`flash_address_adapted`，也不写引导、分区表、OTA、PHY 文件。
